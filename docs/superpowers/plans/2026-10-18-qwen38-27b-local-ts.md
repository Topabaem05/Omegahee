# Qwen3.8-27B 로컬 최대 TPS 연구 계획

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development
> (recommended) or superpowers:executing-plans to implement this plan task-by-task.
> Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Qwen3.8-27B를 이 Mac(Apple M5 Pro, 48GB)에 하드 설치해, 물리적으로 가능한 최대
tok/s를 측정·기록하고 재현 가능하게 만든다.

**Architecture:** 두 축으로 나눈다. (A) 엔진 축은 uzu 0.6.9의 Metal 커널 경로를 이
기기에 맞춰 선택·튜닝한다. 현재 라우팅 테이블에 M5 Pro 항목이 없어 M5 Max 경로로
떨어진다. (B) 모델 축은 같은 모델의 여러 양자화 변형을 받아 품질과 속도를 함께 재고,
품질 기준을 통과하는 가장 빠른 변형을 고른다.

**Tech Stack:** uzu 0.6.9(릴리스 바이너리, Metal), Mirai-M 4비트 체크포인트,
unsloth GGUF 변형, Python 측정 하네스, macOS 27.

**Spec:** `docs/problem_report_20261017.md`, `docs/budget_measurement_20261018.md`,
`docs/step3_gemv_byteorder_20261018.md`.

## Global Constraints

- 기기: Apple M5 Pro, 16 GPU 코어, 48GB 통합 메모리, macOS 27.0, Metal 4.
- 디스크 여유 8.8GB. 작업 시작 전 최소 45GB 확보가 선행 조건이다(27B Mirai-M 14.53GB
  + speculator 1.03GB + 여유).
- 측정은 단일 실행으로 판단하지 않는다. 예산당 최소 10표본, 표준편차를 함께 기록한다
  (`docs/budget_measurement_20261018.md`에서 단일 실행 비교가 무효임을 확인했다).
- 품질 기준을 통과하지 못한 변형은 속도 순위에 넣지 않는다.
- 유휴 상태 측정: `vm.swapusage` used가 1GB 미만일 때만 측정값을 채택한다.
- 모든 수치는 재현 명령과 함께 `docs/`에 남긴다.

## Review Focus

- 열 스로틀링: 27B는 14.5GB를 매 토큰 읽는다. 30초 이상 연속 실행하면 클럭이
  떨어질 수 있고, 짧은 실행만 재면 낙관 편향이 생긴다.
- 스왑 오염: 다른 앱이 메모리를 쓰면 모델 페이지가 디스크로 밀려 tok/s가 절반이 된다.
- 측정 대상 혼동: TTFT(프리필)와 생성 tok/s를 섞으면 결론이 뒤집힌다.
- 품질 회귀: 빠른 변형(IQ1/IQ2)이 목표 점수를 못 넘을 수 있다.
- 캐시 효과: 같은 프롬프트를 반복하면 KV·페이지 캐시가 따뜻해져 과대 측정된다.

## 예상 병목과 근거

| 병목 | 근거 | 예상 영향 |
|---|---|---|
| M5 Pro 라우팅 부재 | `routes.rs`에 M5 Max만 존재 | 타일 오선택 |
| 디스크 8.8GB | 27B 14.53GB 필요 | 착수 불가 |
| 측정 변동 | 9B에서 표준편차 16 tok/s 관측 | 결론 오염 |
| 스왑 | 현재 10.6GB 사용 이력 | 최대 2배 손실 |
| 가중치 14.53GB | 4.61 bpw | 이론 상한 약 13–29 tok/s |

마지막 항목이 중요하다. 48GB에서 14.53GB를 매 토큰 읽으므로 이론 상한이 낮다.

측정 대역폭(406.7 최고 / 366.3 중간값 / 250 보수적 GB/s)으로 계산한 배치 1 디코드 상한:

| 구성 | 가중치 GB | 최고 | 중간값 | 보수적 |
|---|---:|---:|---:|---:|
| Mirai-M 4.61 bpw | 15.57 | 26.1 | 23.5 | 16.1 |
| GGUF Q4_0 | 16.06 | 25.3 | 22.8 | 15.6 |
| GGUF IQ3_XXS | 10.93 | 37.2 | 33.5 | 22.9 |
| Omega-Uzu 2.38075 bpw | 8.04 | 50.6 | 45.6 | 31.1 |

즉 27B Mirai-M의 현실적 상한은 **16–26 tok/s**다. 2.38bpw로 가면 **31–51 tok/s**로
두 배가 된다. 이것이 Omega-Uzu 작업이 27B에서 갖는 의미이며, 사용자가 기대할 수 있는
숫자의 범위다. 이 표를 넘어서는 주장(예: 100 tok/s)은 투기 디코딩 없이는 물리적으로
불가능하다.
